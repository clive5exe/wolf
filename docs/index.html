WOLF
watches obsessively, lacks feelings

The model advises. Your machine decides.

An AI portfolio runtime for macOS and Linux. An LLM can read the market and argue a case; it cannot touch a position limit, a loss limit, or the kill switch. Those are ordinary, fully-tested code with absolute veto.

Quick start
macOS & Linux
# Prints what it will do before doing it. No sudo, no account. $ curl -fsSL https://raw.githubusercontent.com/clive5exe/wolf/main/install.sh | sh $ wolf setup

Prefer to read it first? Swap | sh for | less — it touches two paths and prints them before it starts. Then wolf setup turns your goals into a policy you confirm field by field.

The interface

Six screens, one keystroke apart

Real captures, produced by running the app — not mockups. Every figure on them is one the code actually computed.

The den
One row answers five questions per holding: how much, how far from plan, what it costs, how fresh the price is. The ◆┼ gauge shows drift spatially, scaled so the end of the track is the point where the strategy trades.
Decision cycle
Watchable as it happens. Stages complete left to right, so you can see the model occupy exactly one box — with deterministic walls on both sides.
Verdict
Thesis on top, the rule wall below, receipt at the bottom. Every rule is listed, every time — including on a veto, when it would be easiest to summarise.
Boot
The environment checks are the startup sequence. A failing check halts the cascade with its fix hint, so you cannot boot past a broken setup.
Journal
Vetoes and no-actions carry the same weight as fills. "We did not trade" is a result, not an absence.
Kill switch
Reachable from anywhere with one key, checked at four separate layers, and deliberately the ugliest thing in the app. Disengaging takes two intentional presses or a typed command — safety should not be tasteful.
How a decision works
  1. 1.
    Observe, then retrieve.
    Positions and quotes are read, then assembled into a context package where every item carries a source, a timestamp, a TTL and a credibility score. Stale data is a stop sign: "insufficient or stale data, no action" is a successful outcome.
  2. 2.
    Propose deterministically.
    The strategy computes candidate trades in explicit Decimal arithmetic. Sizing is never a model's job — it is arithmetic, and arithmetic belongs to code you can read.
  3. 3.
    Ask the model for judgement.
    Optionally. It receives proportions, never amounts — "39.9% of the portfolio against a 40% target", never a dollar figure or a share count. It returns a structured thesis with citations, or nothing.
  4. 4.
    Run every rule, every time.
    Twenty-one deterministic checks — position and sector caps, loss limits, cooldowns, trading hours, quote and context staleness, duplicate orders, the kill switch. Any blocking failure vetoes the trade. The model has no say here at all.
  5. 5.
    Record it so it can be replayed.
    Context, thesis, every rule result, fills and notifications land in an append-only log that replays byte-identically. The database refuses UPDATE and DELETE outright.
Why it is built this way

Trust is earned with evidence, not disclaimers

✓
Deterministic code disposes
An LLM may synthesise research and draft a thesis. It cannot touch limits, hours, symbol permissions, or the kill switch. Only the risk engine can issue an order, and broker adapters accept nothing else.
●
Freshness is never hidden
Nothing enters a decision without an event time, an ingestion time and a TTL. Live sources pulse on screen; stale ones go still, so you notice the absence of motion.
⌂
No service behind it
No account with us, no backend, no telemetry. Your history is a SQLite file you own. It does use the network — your AI provider, your broker, public filings — always through your own credentials.
What it does not do

The limitations, up front

A project that argues for honest software should be honest about itself. This list is maintained in the README too.

  • ✕
    It does not trade real money yet.
    v0.1 is read-only intelligence plus paper trading. The paper engine exercises the identical proposal → risk → order path live execution will, so the evidence is comparable rather than a toy. Human-approved execution is the next milestone.
  • ✕
    It is not investment advice.
    Experimental research software. Nothing it produces predicts markets, and no output should be treated as a recommendation to buy or sell anything.
  • !
    Some statistics report "unavailable".
    Sharpe, Sortino and beta need a benchmark series that is not yet configured, so they say so rather than being approximated. The dashboard likewise draws no per-symbol sparkline, because no price history is stored and drawing one would be invented.
  • !
    The market clock is holiday-naive.
    It knows regular NYSE hours but not the exchange holiday calendar. Paper mode simulates sessions; live modes require a holiday source before enabling trading-hours enforcement for real orders.
  • !
    Windows is untested.
    macOS and Linux are covered by CI. Nothing is known to break on Windows, but nobody has run it — and an untested claim is one you get called on.
