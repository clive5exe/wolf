WOLF

An AI portfolio runtime. The model advises; deterministic code decides. This covers installing it, giving it a policy, and understanding what happens on every cycle.

v0.1 is paper trading only. There is no real-money execution path in this build — not disabled, absent. Experimental research software, not investment advice.

Install

macOS and Linux. Needs Python 3.12+ and git.

# prints what it will do before doing it
curl -fsSL https://wolf.clive5.com/install.sh | sh

It clones into ~/.wolf, creates an isolated virtualenv, and links wolf into ~/.local/bin. No sudo, nothing system-wide, no account. Swap | sh for | less to read it first. Set WOLF_HOME to relocate, or WOLF_REF to pin a tag.

Check the environment at any time:

wolf doctor

It reports platform, Python, event store, provider, policy, risk rules, kill switch, secret store, and notifications — each with a fix hint rather than a stack trace.

Create a policy

wolf setup

Describe what the portfolio is for in plain words. A model drafts a starting point, and you confirm every enforceable field before anything activates. Three things hold here:

  • The draft cannot decide. Its schema has no field for trading mode or autopilot, so it cannot express "trade for real" or "trade unattended".
  • A draft can narrow a limit, never widen one. A model suggesting a 90% position cap is held at 25% — and the clamp is shown to you, because quietly discarding a suggestion is its own dishonesty. You can still type something wider yourself.
  • Loss limits are beyond its reach entirely. Daily loss, drawdown, order rate, and staleness thresholds cannot be suggested at all — only set by you or left at defaults.

Setup always produces paper mode. Moving up is separate and deliberate.

Run a cycle

wolf tui        # enter the den
wolf demo --cycles 2   # run cycles from the CLI

In the TUI, c runs a decision cycle and shows it happening stage by stage. ⏎ opens the verdict for the last decision — thesis, every risk rule, and the execution receipt.

Run on a schedule

wolf watch --interval 15m

Runs cycles on an interval, gated to regular market hours by default (--any-hours to override). The scheduler only decides when to ask for a cycle — every rule, the mode gate, and the kill switch apply exactly as they do for a manual run.

On an always-on machine, as a service:

# /etc/systemd/system/wolf.service
[Service]
ExecStart=%h/.wolf/.venv/bin/wolf watch --interval 15m
Restart=always

The decision cycle

Every decision runs the same six stages, and each is recorded.

  1. Observe — read account and quotes.
  2. Retrieve — assemble a context package; every item carries a source, event time, TTL, and credibility.
  3. Propose — the strategy computes candidates in explicit Decimal arithmetic.
  4. Thesis — optional. A model returns a structured argument with citations, or nothing. Skipped entirely on deterministic cycles, which cost $0.00.
  5. Risk — every rule runs on every action. Any blocking failure vetoes.
  6. Execute — paper fills in v0.1, through the same path live execution will use.

Stopping early with a reason is a success, not a failure. "Insufficient or stale data, no action" is a recorded, replayable outcome with the same standing as a fill.

The risk engine

Twenty-one deterministic checks, run on every proposed action, every time. The engine is pure — no I/O, no clock reads — so a verdict is a function of its inputs and replays identically.

Twenty are configured policy rules; the twenty-first is a per-proposal idempotency check that only exists once a proposal does. concentration_advisory is non-blocking — it records without vetoing, and the verdict screen marks it ◇ rather than hiding it.

Only the risk engine can construct a ValidatedOrder, and broker adapters accept nothing else. That boundary is enforced mechanically by the safety suite, not by convention.

Context & freshness

Nothing enters a decision without an event time, an ingestion time, and a TTL. Freshness is computed from age and TTL at read time — never stored — so a persisted item cannot lie about being fresh.

GlyphStateMeaning
●freshage ≤ half its TTL
◐agingpast half TTL, still usable
○stalepast TTL — not decision-bearing
✕absentno data at all

On screen, live sources pulse and stale ones stop moving, so you notice the absence of motion.

The event log

Everything is event-sourced into append-only SQLite. The database refuses UPDATE and DELETE outright — enforced by triggers, not by application code being careful. 

wolf events --limit 20

Event ids are ULIDs, so lexicographic order is creation order and reordering rows cannot reorder history. Replay reproduces state byte-identically, which is the release gate.

No mode may be skipped on the way up; any number may be skipped on the way down. Transitions are policy-version changes, recorded as events.

Files & paths

PlatformData directory
macOS~/Library/Application Support/WOLF
Linux$XDG_DATA_HOME/wolf (default ~/.local/share/wolf)

Override with WOLF_DATA_DIR. An existing pre-rename directory is adopted in place rather than migrated, so no upgrade can orphan an audit log. The database is tradeos.db — deliberately not renamed with the product, because that filename addresses state that already exists on disk.

Kill switch

Checked at four layers: scheduler, cycle, risk engine, and broker. Engage it with k from any screen, or wolf kill "reason".

Disengaging is deliberately awkward — two separate presses in the TUI, or a typed wolf unkill. Never one accidental key. Both paths are recorded with who and when, and the state survives restarts because it is derived from the event log rather than held in memory.

Secrets

Credentials live only in an OS credential store — macOS Keychain or libsecret on Linux. There is deliberately no file fallback. If no keystore is available, WOLF refuses rather than writing credentials to disk, because a silent downgrade would leave a machine unprotected with nothing on screen to say so.

On a headless host with no session keyring, inject them via systemd LoadCredential= rather than a dotfile.

What the model sees

A provider prompt is the one thing that leaves your machine, so it carries proportions, never amounts: "VTI is 39.9% of the portfolio against a 40% target", never $39,914 or 140 shares.

This is not primarily a privacy setting. Every use of an absolute figure is arithmetic, and arithmetic belongs to the strategy and the risk engine — a component supplying judgement has no need of the units. It is enforced by type: the outbound projection has no field capable of holding an amount, so it cannot rot the way a filter would.

Third-party content is exempt. A headline reading "Q3 profit up $2.1B" is public information about someone else and reveals nothing about your portfolio.

Threat model

Every documented threat maps to an executable test, and a meta-test fails if a threat is added to the document without one — so the model cannot get ahead of the code.

ThreatMitigation
T1 — model argues a limit-violating tradeDeterministic veto; thesis schema cannot express an order
T2 — prompt injection via ingested contentUntrusted-data frame, citation integrity, and the T1 chain
T3 — credential theft from diskOS keystore only, no file fallback, redacted logs
T4 — duplicate or replayed ordersContent-addressed order ids, TTL, idempotent executor
T5 — stale-data tradingMandatory TTLs, blocking staleness rules, fail closed
